# skill 依赖解析

> [Study 索引](README.md) · skill 包专题。安装契约在 [使用文档](../usage.md#skill-packs)，实现在
> [`scripts/install-skills.py`](../../scripts/install-skills.py)，这里只记取舍。

> 2026-10 对照两份已有解法。

## 结论

`requires` 里的名字在本次安装的所有来源（agent-loop 与已登记的包）里查，一个名字最多一个可装提供者，没有版本。
所以要的只是两件事：剔除依赖不成立的 skill，直到剩下的都成立；按提供者在前的顺序建链接。前者是不动点剔除，
后者直接用标准库 `graphlib`。不需要回溯求解。

## graphlib：取拓扑序与环报告

[`graphlib.TopologicalSorter`](https://docs.python.org/3/library/graphlib.html) 给出提供者在前的顺序；
图里有环时 `prepare()` 抛 `CycleError`，`args[1]` 是一条环上的节点。

本库取它的顺序与环报告：环上的 skill 记为不可装，再剔除一轮依赖它们的 skill，直到图中无环。
`CycleError` 一次只报一条环，所以循环到无环为止，不假设一次报全。

没取它的增量接口（`get_ready` / `done`）：安装是单线程逐个建链接，`static_order()` 就够。
`done()` 只是告诉排序器「这个节点成功了」，失败时不调用它，依赖者就不会就绪；本库用 `Skill.problem` 加一个
失败名集合做同一件事：轮到依赖者时，它的某个 `requires` 在失败集合里就跳过。两者都只管顺序，不管文件系统，
所以旧链接的删除与替换必须放进逐项应用的那一步，而不是在排序之前批量做：批量删掉的依赖者旧链接，
在提供者失败后已经无法保留。

## pip 的依赖解析：不取

[pip 的 resolver](https://pip.pypa.io/en/stable/topics/dependency-resolution/) 解决的是「一个名字有多个版本，
选一组彼此兼容的版本」，因此需要回溯：选了某个版本后发现冲突，退回去换一个。

这里每个名字的提供者在依赖解析之前就已经唯一确定了：同名出现在两个来源时两个都跳过，不挑一个。没有可选项，
也就没有可回溯的分支；剔除一个 skill 只会让依赖它的 skill 也不可装，不会让别的选择变得可行。
pip 的回溯、版本约束与 `ResolutionImpossible` 的解释都不适用。

## 剔除顺序

1. 名字冲突与目标冲突先判：与 agent-loop 重名、多个包重名、目标位置已有非受管理条目。
2. 不动点：一个 skill 的某个 `requires` 不在剩余集合里，就剔除它，重复到没有变化。缺失、未选中、
   上一步被剔除的名字都走这一条，间接依赖者因此也被剔除。
3. 对剩余集合求拓扑序；有环则剔除环上的 skill，回到第 2 步。
4. 按拓扑序逐个应用：替换指向登记来源的旧链接、建新链接。某个 skill 失败（目标是普通目录、外部链接，
   或删除、建链接的系统调用报错）时，依赖它的 skill 在轮到时被跳过，它们已有的链接不动。
   Cursor 上核心 skill 在 `skills-cursor/`、包 skill 在 `skills/`，一个 skill 迁出后它的旧链接与新链接不在同一目录；
   两个目录里同名的受管理旧链接都归这个 skill，在它这一步先退役再建新链接，退役失败就是它的失败。
   不再属于任何本次候选的旧链接单独撤，撤不掉只报告并非零退出，不中断安装。

一条规则管住所有旧链接：**一个名字只要还是本次被选中的候选（agent-loop 的 skill，或 profile 选中的包 skill），
它的链接只由它自己的应用步骤改动；不是任何候选的名字，才归剩余清理。** 被剔除（名字冲突、目标冲突、依赖不成立，
或上游应用失败）不等于退出本次选择，所以这些候选的旧链接原样保留；未选中、已从 manifest 删掉的 skill 才被撤掉。
一个候选自己的应用步骤开始后才失败（旧链接已撤、新链接没建成）时，可能留下部分状态；安装器不回滚，
重跑是恢复路径。不做回滚，是因为链接可以由下一次安装确定地重建，而事务化需要额外的持久状态。

合成的 manifest、调用与输出见 [`tests/test_skill_dependency_resolution.py`](../../tests/test_skill_dependency_resolution.py)。
