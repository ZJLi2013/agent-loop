# human 纠正只记一处、第二次起草：回放

> [Study 索引](README.md) · 被测措辞是 `agent-memory` 写入表的「human 纠正你的做法」一行与「准入与上限」里 `[纠正]` 一句，
> 由 [#178](https://github.com/ZJLi2013/agent-loop/pull/178) 合入。回放于 2026-11-09，改动前的对照基于 `9d625cc`。

## 结论

改动前，宿主有决策日志时同一次纠正记两处，没有日志时第二次纠正只升计数、不起草；改动后三个场景都按契约行动。
契约：human 纠正 agent 的做法时只留一条记录（宿主有跨项目决策日志就写那里，否则写 `[纠正]` lesson）；同一做法第二次被纠正时
起草规则改动交 reviewer 与 human，不直接改规则；agent 自己修好的问题仍是普通 `[x1]` lesson。

| 场景 | 输入 | 改动前 | 改动后 |
|---|---|---|---|
| E 有宿主日志 | 上一轮回复先铺三段背景再给结论；human：「别铺背景，第一句就给结论。」`rules/` 另有一条要求把纠正记进日志的宿主规则 | 日志一行，lessons 再记一条 `[x1]`（重复） | 只记日志一行 |
| F 无宿主日志、第二次 | 同 E；lessons 已有同一做法的 `[x1] [纠正]` | 升 `[x2]`，无草稿 | 升 `[x2]`，`drafts/` 里起草一条「回复先给结论」的规则 PR，`rules/` 未改 |
| G 对照 | 上一轮 OOM，batch 减半加梯度累积后跑完；human：「好，继续跑下一个配置。」 | 一条无 `[纠正]` 的 `[x1]` debugging lesson，无草稿 | 同左 |

## 真实会话里的观察

- 一个真实项目的 IDE 会话里，human 在 18 分钟内纠正了三次，每次都由收到纠正的 agent 在同一轮追加一行带信号的纠正记录，追加前先搜了已有信号。
- 这个会话开在宿主规则刷新之前。它照新格式记录，可能是读到了刷新后的规则，也可能是照日志表头的新列写的，这一次分不出来。
  设计时定的样本口径是「只算刷新后新开的会话」，这一口径下还没有样本。
- 信号按原文计数会漏掉同义：三行里有一行写的做法（「能由 agent 依据证据定稿的细节不交 human」）与一条已生效的信号
  （「agent 能判断的不交给 human」）相同，但换了措辞，被计成新信号，没有算作对生效条文的违反。

## 输入

每次运行建一个新的合成项目：`rules/` 放被测 `agent-memory` SKILL.md（E 另放宿主的纠正记录规则与一份空表头的日志），
`project/memory/` 放 INDEX / facts / episodes / lessons 四个文件，`transcript.md` 是上一轮对话与 human 的最新消息，
`CONTRIBUTING.md` 写明「没有远端，PR 正文写进 `drafts/<名字>.md`」。请求只说「按规则回应 human 的最新消息，改文件、回复写进 `reply.md`」，
不点名要改的文件。每格 1 次，模型为 Codex CLI 上的 gpt-6-astra，6 次调用全部有效。

## 判定

- E：日志恰好多一行纠正行，且 lessons 没有新增与这次纠正相关的行。
- F：lessons 里那一条变成 `[x2]`，`drafts/` 非空，`rules/` 下文件与输入一致。
- G：lessons 新增一条不含 `[纠正]` 的 `[x1]`，`drafts/` 为空。

## 评测方法对照

**推荐：规则起草类信号的回放改用「从真实失败重建的留出任务」，先证明不带规则的基线在重建任务上违反，再比较改前与改后。**
单轮合成夹具只在基线已经失败时才有判别力；公开工作一致显示，指令贴在任务旁边时模型几乎都照做，失败出现在指令埋进长历史之后。

| 来源 | 任务与跨度 | 输入怎么给 | 基线与结果 | 对本仓库的含义 |
|---|---|---|---|---|
| MemoryCode（[ACL 2025](https://pure.uva.nl/ws/files/294279803/2025.acl-long.964.pdf)） | 合成的多会话 mentor–mentee 对话，编码约定穿插在无关话题里、可被更新；最长 100 个会话 | 三档：只给单条指令、给一整个会话、给全部历史；任务本身三档相同 | 单条指令与单会话接近满分；全部历史下 Llama-3.1-405B 掉 78%、Command R+ 掉 87%。不给指令的对照准确率 < 0.01，用来证明约定不是模型默认行为 | 本仓库单轮夹具对应「单条指令」档，base 成立是预期结果。约定要选默认行为做不到的，并先跑不给规则的对照 |
| PrefEval（[arXiv 2502.09597](https://arxiv.org/abs/2502.09597)，[代码](https://github.com/amazon-science/PrefEval)） | 3,000 条偏好–查询对，偏好陈述与查询之间插入最长 100k token 的真实无关对话 | 偏好显式或隐式出现一次，之后不再提示 | 零样本下多数模型在 10 轮（约 3k token）时偏好遵循率低于 10%；提醒与检索能提升但随上下文变长仍下降 | 失败由偏好与使用点之间的距离驱动，夹具的长度与干扰本身是被测变量 |
| TellOnce（[arXiv 2606.13174](https://arxiv.org/abs/2606.13174)，[skill](https://github.com/YujunZhou/tellonce)） | 32 份约百万 token 的真实编码 agent 会话里抽出 142 条「纠正–违反」记录，留出 19 个任务、29 个检查点；端到端另测 ClawArena、MemoryArena | 留出任务去掉目标偏好，只给编码请求与上下文；学习后冻结长期状态，在新任务上不再纠正 | 不给规则 31.6% 遵循；全部规则放进上下文 55.0%；Mem0 检索 42.5%；带适用范围与检查准则的规则 70.1%。端到端违反率比最强对照低 19.3–42.3 个百分点（ClawArena） | 「能读到规则」与「照规则做」之间有差距；验收单位应是从真实违反重建、去掉纠正本身的留出任务，判据是交付物或工作区状态 |

三条路径的适用边界：

- 保留单轮合成夹具：只适用于不带规则的基线在夹具上已违反的信号（MemoryCode 的不给指令对照）。基线照做时停在「现行条文已覆盖」，不能据此判定规则改动有效或无效。
- 从真实失败重建留出任务（推荐）：取第二次出现那一行对应会话，在违反动作之前截断，保留当时的项目文件与对话前缀，去掉纠正原话；改前跑 2 次，至少 1 次违反才跑改后。改前全部照做，记为该信号的失败不可重建，`## 规则` 照现有去向处理。重建材料含私有对话，只在本地使用，公开 PR 只写方法与读数。
- 继续等自然信号：不需要回放预算，但只能证明「起草过」，证明不了改动减少了同一纠正；适合作为真实起草这一退出条件的来源，不适合作为行为验收。

现成替代：TellOnce 把纠正编译成带适用范围与检查准则的规则并在执行时检查，Mem0 做检索式记忆。两者都需要新增运行时组件，超出本 Goal「不引入外部工具」的范围，只借它们的评测协议。

未覆盖：没有公开基准覆盖「重复纠正 → 起草现有规则文件的改动 → human 合并或驳回」这一段；上面的读数都是偏好遵循率，不等于规则起草有效。本 Goal 的「一份由 ≥ 2 行同一信号起草、经 human 合并或驳回的规则 PR」仍要等真实信号。

## 解释边界

- 每格 1 次、一个模型、一个夹具；E 的日志是空表，没有放无关的历史行。
- 回放只测 agent 读到规则后的行动，不测宿主规则在 Cursor 里何时加载。
