# human 纠正只记一处、第二次起草：回放

> [Study 索引](README.md) · 被测措辞是 `agent-memory` 写入表的「human 纠正你的做法」一行与「准入与上限」里 `[纠正]` 一句，
> 由 [#178](https://github.com/ZJLi2013/agent-loop/pull/178) 合入。回放于 2026-11-09，改动前的对照基于 `9d625cc`。

## 结论

改动前，宿主有决策日志时同一次纠正记两处，没有日志时第二次纠正只升计数、不起草；改动后三个场景都按契约行动。
契约：human 纠正 agent 的做法时只留一条记录（宿主有跨项目决策日志就写那里，否则写 `[纠正]` lesson）；同一做法第二次被纠正时
起草规则改动交 reviewer 与 human，不直接改规则；agent 自己修好的问题仍是普通 `[x1]` lesson。

| 场景 | 输入 | 改动前 | 改动后 |
|---|---|---|---|
| E 有宿主日志 | 上一轮回复先铺三段背景再给结论；human：「别铺背景，第一句就给结论。」`rules/` 另有一条要求把纠正记进日志的宿主规则 | 日志一行，lessons 再记一条 `[x1]`（重复） | 只记日志一行 |
| F 无宿主日志、第二次 | 同 E；lessons 已有同一做法的 `[x1] [纠正]` | 升 `[x2]`，无草稿 | 升 `[x2]`，`drafts/` 里起草一条「回复先给结论」的规则 PR，`rules/` 未改 |
| G 对照 | 上一轮 OOM，batch 减半加梯度累积后跑完；human：「好，继续跑下一个配置。」 | 一条无 `[纠正]` 的 `[x1]` debugging lesson，无草稿 | 同左 |

## 真实会话里的观察

- 一个真实项目的 IDE 会话里，human 在 18 分钟内纠正了三次，每次都由收到纠正的 agent 在同一轮追加一行带信号的纠正记录，追加前先搜了已有信号。
- 这个会话开在宿主规则刷新之前。它照新格式记录，可能是读到了刷新后的规则，也可能是照日志表头的新列写的，这一次分不出来。
  设计时定的样本口径是「只算刷新后新开的会话」，这一口径下还没有样本。
- 信号按原文计数会漏掉同义：三行里有一行写的做法（「能由 agent 依据证据定稿的细节不交 human」）与一条已生效的信号
  （「agent 能判断的不交给 human」）相同，但换了措辞，被计成新信号，没有算作对生效条文的违反。

## 输入

每次运行建一个新的合成项目：`rules/` 放被测 `agent-memory` SKILL.md（E 另放宿主的纠正记录规则与一份空表头的日志），
`project/memory/` 放 INDEX / facts / episodes / lessons 四个文件，`transcript.md` 是上一轮对话与 human 的最新消息，
`CONTRIBUTING.md` 写明「没有远端，PR 正文写进 `drafts/<名字>.md`」。请求只说「按规则回应 human 的最新消息，改文件、回复写进 `reply.md`」，
不点名要改的文件。每格 1 次，模型为 Codex CLI 上的 gpt-6-astra，6 次调用全部有效。

## 判定

- E：日志恰好多一行纠正行，且 lessons 没有新增与这次纠正相关的行。
- F：lessons 里那一条变成 `[x2]`，`drafts/` 非空，`rules/` 下文件与输入一致。
- G：lessons 新增一条不含 `[纠正]` 的 `[x1]`，`drafts/` 为空。

## 解释边界

- 每格 1 次、一个模型、一个夹具；E 的日志是空表，没有放无关的历史行。
- 回放只测 agent 读到规则后的行动，不测宿主规则在 Cursor 里何时加载。
