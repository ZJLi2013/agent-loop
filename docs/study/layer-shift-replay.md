# 改假设时换一层：回放

> [Study 索引](README.md) · 被测措辞是 `experiment-design` Phase 3、`when-to-stop` 的「假设被推翻」一行与 task reviewer 第 2 步，
> 对应 [#141](https://github.com/ZJLi2013/agent-loop/issues/141)。回放于 2026-11-02，组件层改动前的对照基于 `d07a682`，
> Goal 层改动前的对照基于组件层提交 `1e8fdde`。

一条规则分两层验收：组件层（同一组件内第二个假设被推翻）留下三处措辞；Goal 层四处候选措辞只有 task reviewer 那一句留下，
另外三处改动前已经成立，不加。

## 组件层结论

改动前，关于同一组件内部的第二个假设被推翻后，worker 与 reviewer 大多继续写下一个局部假设或局部调研；加上三处措辞后，
两条路径在第二次推翻时都上移到组件 / 方法类别的对照，第一次推翻时仍留在局部。两条路径改动前都没做到，三处措辞都留下。

| 路径 | 场景 | 改动前上移 | 改动后上移 |
|---|---|---|---|
| reviewer（`harness/prompts/task_review.md`） | C1：第二个假设被推翻 | 0/2 | 2/2 |
| reviewer | C2：第一个假设被推翻 | 0/2 | 0/2 |
| worker（`experiment-design`、`when-to-stop`） | C1 | 1/2 | 2/2 |
| worker | C2 | 0/2 | 0/2 |

改动前 reviewer 在 C1、C2 都写了「对照领域结论与业界已有解法」的调研 task：第 2 步原有的那句不区分第几次推翻，
调研的对象是下一个局部候选。worker 改动前有一次自己停下，把「继续投资自建组件还是重选方案」交给 human；另一次设计了第三个局部假设。

## 输入

合成项目：一个机械臂 pick 项目，Goal 是 lower_shelf 的 pick 成功率达到 80%，且自由段不退回碰撞盲直线。规划器是自建的
「软代价 IK + 轨迹优化」sidecar，项目文档写着它没在公开基准上测过。两个已关闭 task 各推翻一个关于 sidecar 内部的假设：
t1 的「IK 种子随机」，t2 的「选解只看位置」。

- C1：t2 刚关闭，候选表里的下一条是 t3「world 碰撞 margin 调小」，仍是 sidecar 内部的假设。
- C2：只有 t1 关闭，候选表里的下一条是 t2。

reviewer 路径走真实的 `init` → `verify` → task reviewer 调用；worker 路径是一次调用，只给 `experiment-design`、`when-to-stop`
与项目文件，请求是中性的「写出下一步」。每格 2 次，模型为 Codex CLI 上的 gpt-6-astra（reasoning effort high）。
16 次调用全部有效，用的是同一份夹具。

## 判定

上移指这一步把「留着还是换掉这个组件 / 方法类别」当成要回答的问题或要给出的结论：reviewer 写出这类调研 task，或 worker 停下交 human
定修还是换。只评估下一个局部候选（margin、朝向）有没有依据的调研，即使提到已有方案，也算局部。关键词归类不可用：
改动前 reviewer 的泛化调研在 C1、C2 都命中「替代」「类别」。

## 解释边界

- 每格 2 次、一个模型、一个夹具；判定由 agent 按上面的口径人工完成。
- 两条边界判定都记作局部：改动前 reviewer C1 第 2 次对照了已有方案与 sidecar 的适用条件，但结论是「下一步方向」；
  改动后 reviewer C2 第 2 次把现成替代当背景，要回答的仍是朝向候选有没有依据。前者改判上移，reviewer 改动前的 C1 也只到 1/2，结论不变；
  后者改判上移，reviewer 措辞在第一次推翻时就有一次误触发，误触发的代价是一个只查资料的 task。

## Goal 层

合成项目的 Goal 是「在真实场景孪生里评测 VLA：7 个 scenario 中至少 2 个 certified」，当前 0/7。正例 G1 的两个已结束阶段
各排除了一个抓取失败原因，Goal 退出条件未动；对照 G2 的两个阶段只搭建了场景导入器与评测器。写新 Goal 的三个场景：P1 项目文档记着
「规划失败退回直线，已在两个 Goal 里绕开」；P2 是 human 把定位从合成数据生成改为真实场景孪生评测，主线有三个旧 Goal；P3 与 P1
同一请求，文档里没有那条阻塞。外部资料由夹具里的合成笔记提供，被测的是会不会对照，不是会不会检索。

| 契约 | 正例 / 对照 | 改动前 | 改动后 | 处置 |
|---|---|---|---|---|
| reviewer：两个排除原因的阶段不动 Goal 时 `ask_human`，后继是 Goal 与公开工作的对照 | G1 / G2 | 0/2 · 0/2 触发 | 2/2 · 0/2 触发 | 留下 |
| worker（`experiment-design`）：同上，交 human 或对照公开工作 | G1w / G2w | 2/2 · 0/2 触发 | — | 不加 |
| `work-planning`：新 Goal 写明未解阻塞的影响 | P1 / P3 | 2/2 · 0/2 触发 | — | 不加 |
| `work-planning`：改定位时链接外部对照，旧 Goal 逐项 keep / revise / drop | P2 / P3 | 2/2 · 0/2 触发 | — | 不加 |

- 改动前 reviewer 在 G1 两次都选 `continue`，后继是操作层的方案调研，问题停在组件层。
- 改动前 worker 在 G1w 两次都停下交 human，依据是现有的决策门与「有显著权衡的方案间选型」；P1 两次都把直线回退列为评测有效性的前置检查；
  P2 两次都点名公开工作、写出本项目增量，B、C 两个旧 Goal 都 drop，C 的理由是不再自建规划、真缺时借用现成库。`work-planning` 与 `experiment-design` 现有措辞已覆盖这三处，推翻条件是
  同类场景改动前正例 0/2。
- reviewer 的首稿「结束的是第二个排除了 Goal 未达成原因、而 Goal 退出条件仍未动的阶段」在 G2 两次误触发：模型把两个搭建阶段读成
  「两个阶段结束、certified 仍为 0/7」。现行措辞写明两个阶段的结论都是排除了一个原因，并排除只搭建前置能力的阶段。
- 夹具的 certified 定义要求真机成功率，夹具没给真机读数；G2w 两次都因此停在 Phase 0 的输入缺口上，判作未触发 Goal 层上移。
- 每格 2 次、一个模型、一个夹具，判定由 agent 人工完成。
