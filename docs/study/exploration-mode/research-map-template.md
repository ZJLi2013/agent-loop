## 规则

### 两个阶段

- **信号阶段先于搜索。** `Phase: signal` 时只做两类 probe：造信号、读文献。信号要写清测量什么、相对什么基线、覆盖哪个子假设，
  并在至少一个已知阴性案例和一个已知或构造的阳性案例上给出预期方向的值，测出单次成本，才转入 `Phase: search`。
  不同子假设用不同信号，不能用一个替代另一个。
- **信号带版本号。** 改信号定义要 human 决定，并写进新版本；旧版本上的结论不自动迁移。

### 分支与 probe

- **分支是争夺研究预算的切入方式，不要求结论互斥。** 初始列出 3–5 种；写明共享前提与依赖。同一载体上的连续候选算一个分支，
  不能当成全部分支。
- **probe 是一次检验**，一个调研来源或一次运行。Probe 记录是唯一事实源，分支的 probe 数与时间盒的 probe 数由它派生。
- **排序跨分支比较**：按预期信息量 ÷ 成本，写明依据；上限未知的分支先排测上限的 probe；相近时优先 probe 少的分支。
- **每个 probe 都写「地图改变了什么」**：剪掉、提升、改了某个信号值。只有新证据支持的重排才算变化；写不出就是零信息 probe。
- **有效性**：probe 只做预算内、直接关系到这次结果能否解释的最低检查。检查不过记为「无效」或「未决」，不作证伪证据，
  也不扩展成准入审批。
- **剪枝不删行**：分支行保留并把状态改为「剪掉」；「已剪掉」表只记引用、理由与复活条件。

### 收敛

- 负结论必须对应已触发的证伪条件，并限定于已检验的范围；「未测」不按低值处理。
- 预算或时间盒用完记为「未决停止」，不是负结论。

### 预算

- 时间盒声明墙钟、算力、probe 数与单个 probe 上限；准备、调试和修订都计入。任一上限达到即结束时间盒。
- 同类重复动作（同一检索、同一调试、同一修订）超过 3 次即停，记入 Probe 记录。

### 人与 reviewer

- human 在开始时给出或确认根问题、价值与收敛条件；可以随时增加分支、重排顺序；时间盒末按分支写剪枝 / 继续 / 提升及理由。
- reviewer 在时间盒末给建议，不批准 probe，不审完整协议：竞争切入方式是否列全，排第一的 probe 是否信息量最大，
  证伪条件能否真的剪掉分支（把分支拆成假设逐条核对），以及跨时间盒反复出现的问题。

### 告警（不阻断）

触发后先回到根问题，比较各切入方式、检查门槛与成本，再决定是否继续同类工作：

- 连续 3 个 probe 都落在同一分支的下一个候选上，期间没有跨分支比较；
- 连续 3 次地图修订没有新的 probe 证据；
- 进入搜索阶段前就开始搭完整系统。

### 提升

同时满足才提升：

1. 假设能用一句话写清，成立与不成立指向不同的下一步；
2. 有可执行的验收判据：任务指标，或已在阴性 / 阳性案例上验证过的信号；
3. 预计成本值得 plan / review / verifier 的门槛。

提升时按确认模式现有的格式交接，不给它增加字段或门槛：写一个 proposed Goal 与首个 task（一个未验证假设、验收检查点、
失败去向、预算，链接设计），由现有的 plan review 与 human 批准接手。分支状态改为 `promoted` 并链接 plan；
确认模式的结果由探索侧回填本地图。
