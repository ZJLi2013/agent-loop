# 入口文档的逻辑可读性（#237）

**实验线入口要像一份好汇报：human 从项目 readme 一跳打开它，只读首屏就答得出确立了什么（带关键数）、卡在哪、下一步需要什么。** 本页记录入口的结构、支撑它的证据与评测方法的选择；条文落在 `experiment-design` CLOSE self-audit 第 1 项、`task_review.md` 第 1 步、`work-planning` 文档表与 CLOSE lint（[#237](https://github.com/ZJLi2013/agent-loop/issues/237)）。

## 入口文档的约束

适用于 task CLOSE 写入或改动了项目实验记录的实验线，入口就是该线的 readme：

| 部分 | 所有实验线与 Goal 入口 | 只在研究型实验线 |
|---|---|---|
| 标题 | 一句结论，不写主题名 | — |
| 首屏 | 第一个二级标题前的字段行 `目标`、`现状`、`下一步`，每行一句白话，带改变下一步的关键数，限制条件半句并入同一行 | 另加 `原因` 与 `已排除`（没有就省）；非实验入口用 `卡点` 代替 `原因` |
| 正文 | 只有一张子文档表：序号、名称、回答什么、答案、链接 | 名称列写原实验编号加一句话 |
| 其余 | 数据、设计、读数与重跑都在子文档；不建通用术语节，实验专有词在首次出现处半句带过；不写要 human 选的做法与 task 状态 | — |

- 子文档文件名是两位序号加问题名（如 `01-does-continued-training-help.md`），原实验编号只出现在表的名称列与子文档首行。
- 项目 readme 的索引行是一句当前事实加直达实验线入口的链接，不套第二层纯链接 readme。
- 执行点：CLOSE lint 拒绝本 task 改过的实验线 readme 缺首屏字段、readme 里纯链接的索引行，以及 `exps/` 下新增的以代号开头、没有序号的文件名；task reviewer 只读首屏答三问，答不出或缺关键数报 `must`，术语顺序、去重与表形只报 `suggest`。
- 步骤与数据流只要求读者复述得出事实，不规定步骤表、数据清单或合计的形式。
- 下文证据与评测方法各节测的是此前的五项固定约束，编号沿用：1 步骤表、2 训练 / 评估数据清单与合计（2a / 2b）、3 术语先定义、4 说明只写一次、5 不写待选做法与 task 状态。

## 证据

来自一个机器人 world-model 实验项目的一条数采与 post-train 实验线，入口文档前后三版。

| 版本 | 情况 | 结果 |
|---|---|---|
| 原版（几个 task 均过 CLOSE self-audit 与 task review） | 步骤只以 ①②③ 标签出现在一张漏斗表末列；训练侧组成写了，但分散在一张表与三条条目；两个关键术语无定义 | human 读不出数采是两件事、找不到训练集怎么构成；现行 task reviewer 在这一版上回放 2/2 选 `continue`，未提可读性 |
| 按约束 1–4（不含合计与只写一次）重写 | 新增步骤表、训练 / 评估清单、术语表 | human：仍答不出「实际提供了多少条训练数据」，清单下的逐行说明「太绕」；另指出待选做法表应在 `task.md` |
| 按 human 反馈再改（human 未再读） | 清单上方给出训练侧合计与混入旧数据后的合计，删去重复说明，待选做法表换成一句指针；入口仍有状态行、环状态表与三处「待定」，一个术语先用后定义 | 本页约束 2、4、5 由这一轮反馈得出；逐项核对这一版时约束 3、5 仍不满足 |

原版的三处问题都不是「内容没写」，而是只读入口串不起来；所以约束写成入口的结构要求，不写成「必须包含某项内容」。

## 评测方法的选择

| 参照 | 做法 | 对本库的取舍 |
|---|---|---|
| [Teach-back](https://www.ahrq.gov/health-literacy/improve/precautions/tool5.html)（AHRQ Health Literacy Universal Precautions Toolkit，Tool 5） | 讲解者请对方用自己的话复述，复述不出就说明讲解没讲清，改讲法而不是怪听者 | reviewer 只读入口复述四项，复述不出算入口的缺口；不从 plan 或 Experiment Log 补全 |
| [Diátaxis](https://diataxis.fr/) | 文档按读者任务分为 tutorial、how-to、reference、explanation，不混写 | 入口承担 explanation（步骤与数据流），读数与配方是 reference，留在链接的文档 |
| [Zheng 等，2023，Judging LLM-as-a-Judge](https://arxiv.org/abs/2306.05685) | LLM 评审有位置、冗长与自我偏好等偏差，需要与人工判断对照 | 反例取自 human 读过并指出问题的版本；改后版本 human 未再读，按约束逐项标注而不整例当正例；判分看 `claim` 是否落在标注的缺口行上，不靠关键词匹配 |

验收的标签与结论范围：

- human 反馈与逐项标签分开记。human 原话只说明哪一版读不懂、缺了什么；每一项「能复述 / 部分 / 仍缺失」由入口原件逐项核对得出，不当作 human 的判断。
- 同一份入口允许部分项满足、部分项有缺口。满足项要求 reviewer 复述出事实，缺口项要求它报出缺口；对仍存在的缺口报错不算误报。
- 改后版本相对原版内容与表达都变了，回放通过只说明条文能逐项区分这两版，不说明它能区分只改表达的版本。
- worker 侧：按约束重写入口的那次使用发生在 self-audit 条文改动之前，只是约束的来源，不证明条文生效；条文生效与否，看落地后第一次自然 CLOSE 交出的入口是否不经提醒满足各项。

## 评审方法类别的公开基准与替代

推荐：把入口复述从「自由复述 + 自由写 claim」改成逐项判定——每项约束一个是 / 否判定并带入口行号，判「否」的项逐条转成 `must`，不再由 reviewer 从复述里挑哪些写进 claim。真实回放里丢的正是这一步：首次复述已写出「共享前缀未定义」，最终 claim 没保留。公开结果支持逐项分解比整体判断更一致，但没有一个基准直接测「只读入口能否复述」，所以改后仍要用本页的真实文档回放验收。

| 方法类别 | 原始来源与基准 | 测的是什么、指标 | 结果 | 与本门的对应 |
|---|---|---|---|---|
| 整体打分 / 成对偏好的 LLM 评审（现行做法所属类别） | [Zheng 等，2023](https://arxiv.org/abs/2306.05685)，MT-Bench 与 Chatbot Arena | 偏好判断，与人工偏好的一致率 | GPT-4 与人工一致率超过 80%，同时存在位置、冗长、自我偏好偏差 | 测的是偏好，不测缺口定位 |
| 同类，难题上的正确性判断 | [Tan 等，2024，JudgeBench](https://arxiv.org/abs/2410.12784) | 350 对一对一错的回答，判对准确率 | GPT-4o vanilla 50.86%（约等于随机），Arena-Hard 提示 56.57%；o3-mini high 80.86% | 整体评审在需要逐处核对的任务上不可靠，换提示只小幅改善 |
| 逐项是 / 否清单（替代一） | [Qin 等，2024，InFoBench](https://arxiv.org/abs/2401.03601)（500 条指令、2,250 个分解问题） | 分解要求逐条判，与人工标注的一致性（Kappa） | 分解指标比 1–5 直接打分的标注者 Kappa 高出 0.19 以上；GPT-4 可作低成本标注者 | 对应「每项约束单独判」，正是丢 claim 的那一环 |
| 同上，清单由模型生成 | [Cook 等，2024，TICK](https://arxiv.org/abs/2410.03608)（InFoBench、WildBench、LiveBench） | 与人工偏好的完全一致率 | 46.4% → 52.2%（相对直接打分）；给人工评审配清单，标注者一致性 0.194 → 0.256 | 本门的清单已由约束固定，不需要生成；增益幅度有限 |
| 问答式核对（替代二） | [Wang 等，2020，QAGS](https://arxiv.org/abs/2004.04228)（CNN/DailyMail、XSUM） | 对摘要与原文各问同一组问题，答案不一致即不一致；与人工事实一致性判断的相关 | CNN/DailyMail 上 Pearson 54.52，ROUGE-2 为 17.72 | 对应 Teach-back：从 plan 出题、只用入口作答，答不出即缺口；要两次隔离调用 |

局限：

- 上面的基准测的是指令遵循、偏好或事实一致，没有一个测「只读入口能否复述步骤、数据流与术语」；数字只说明方法类别的方向，不能换算成本门的通过率。
- 逐项判定解决的是「识别到了却没写进 claim」；reviewer 首次复述就没看出的缺口，它不解决，问答式核对才针对那一环。
- 逐项判定的增益在两篇里都是几个百分点到 0.2 Kappa，不保证本门 N2 约束 3 从 1/2 到 2/2。

逐项判定在固定真实输入上未达到联合判定，条文不并入主线：

- 按分号拆成五项的候选（`1115847`）：N2 的 claim 按序带上了全部「否」项，术语缺口这次输出了；但「步骤与衔接」被判「是」。这一版没有按约束拆出六项，只说明该候选失败，不排除逐项判定。
- 按约束 1、2a、2b、3、4、5 拆成六项的候选（`2814bdf`）：N2 的步骤与术语缺口都进了 claim；P2 的步骤已能复述，reviewer 也复述对了，却因评估没在步骤表里单列一步判「否」，在约束 1 上误报。

三轮改动（合计措辞、五项、六项）在「N2 缺口能报出」与「P2 满足项不误报」之间此消彼长：步骤要求写得越具体，越容易把已能复述的步骤也判成缺口。逐项判定解决了「识别了却没进 claim」，没有解决步骤一项的判定边界。

## 入口答与设计答对比（未通过）

选它的理由：步骤一项的误报来自 reviewer 自己补出「应该有哪些步骤」。改成拿 task 链接的设计文档当原文，入口当摘要（QAGS 的做法），步骤与来源的范围就由设计定，不由 reviewer 推测。

- 接口：内容项用固定问题——1a 按顺序做了哪几步、在哪里做；1b 每步输入、产出、交给谁；2a / 2b 训练 / 评估各用哪些来源、各多少、作用、合计。复述文件对每题记「入口答」「设计答」「判定」「缺口」；入口答不出或与设计答不一致判「否」。结构要求（约束 1 的步骤表与衔接句、约束 2 的清单与合计）照旧逐条判，范围以设计里的步骤与来源为准；约束 3、4、5 照旧只读入口判。所有「否」按 1、2a、2b、3、4、5 合成一条 `must`。decision JSON 不变。
- 读取边界：入口答与结构事实写进复述文件之前，只读 task 行、`git diff --stat` 与入口；写完后才读设计文档与 plan 作设计答，不回填入口答。问题是固定模板，不由模型生成，不夹带答案，不增加调用。
- 局限：设计答与入口答出自同一次调用、同一模型，共同的盲点比较不出；设计文档没写清的事，本门不报缺口。

回放结果（候选 `0782a68`，2 次调用后停跑）：N2 的步骤与术语缺口都报出了；P2 的入口答写对了步骤，但 reviewer 把入口同目录里后续 task 的设计也算作本线步骤，判入口的步骤表缺了这些步，约束 1 误报。

连同前三轮，同一门四个候选都没过联合判定，失败都落在步骤一项：N2 漏报，或 P2 误报。各轮误报的直接原因不同（六项候选要求评估单列一步，本候选把后续 task 的设计算进步骤范围），尚未隔离出共同原因。
