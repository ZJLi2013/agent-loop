# Experiment-Driven Documentation

把「假设 → 设计 → 执行 → 结果 → 分析 → 下一步」记进项目文档，让任何人（包括未来的自己）
能复现思路与决策依据。

**边界**：本 skill 是 `agent-loop` 里 DESIGN 那一格——**被选中的那个 task 要跑一轮验证时**
用它。它管两道门与实验文档的章节模板，不管任务怎么排、循环怎么转。

`task.md` 的 schema、验收检查点、失败计数归 `task-loop`；语态归 `narrative-spine`；
「什么情况才停下来问人」归 `experiment-budget-gate`。**本 skill 不定义任何任务清单格式。**

## 两道门

### 决策价值门 — 每轮开跑前必答

> **结果如果是否定的，主线会改变吗？** 不会就不跑，写一行预判代替。

假设成立与否导向同一个动作时，这轮没有信息量。四类零信息实验：**先验就能否掉的**（跨后端算超越函数
不可能逐 bit 一致）、**别处已证过的**（先 grep 已有文档，再决定要不要重跑）、**两个分支同一动作**
（横竖都得走那道门，那就直接走）、**量级估算已判死的**（扰动低于系统自身噪声，测不出来）。

**先对账，再对精度。** 一条候选的收益要先和主线的分段归因对上，且**量级要配得上主线**——
主线瓶颈是 100 ms 级时，不要在 10 ms 级的候选上连开三轮。

这条门对 agent 尤其重要：写实验很便宜（一个脚本、一段 assert），跑实验很贵（engine init、
GPU 占用、大量 token）。**便宜的是写，贵的是跑和读。**

#### 中途岔出去的验证 — 执行期最难自查的一类

它不在开跑前出现，而是在主线跑到一半、冒出一个小小的不一致时出现，且每一步看着都合理。三个真实的例子：
为了解释 A/B 里 6.8 ms 的偏移，补跑一支只差一个 `--flag` 的臂；为了说明 trace 可信，去量
profiler 自身引入多少 latency；为了确认某个判据失效，把已知会失败的对比再跑一遍。
**共同点是它们服务于「把某个数解释干净」，而不是「让主线往前走一格」。**

自查一句：**这个不一致如果永远不解释，主线会卡住吗？** 不会就写一行「差 X，大概来自 Y，不影响结论 Z」
然后继续。**被解释的那个量本身即将被替换时（旧基线、要退役的口径、马上要重测的臂），解释它的价值是零。**

**发现自己已经在岔路上就立刻停，包括杀掉正在跑的任务。** 沉没成本不是继续的理由——跑完还要付读结果、
写结论的 token，而这些产出一开始就没人要。


### 验收判据阶梯 — 从任务指标往下选

**最终判据永远在任务指标上。** 数值等价、op 计数、张量距离都只是「省得跑任务指标」的代理；
代理失效就回去跑正品，不要在代理上继续加码。

| 层 | 判据 | 适用 |
|---|---|---|
| 0 | 纸面量级估算 | 任何数值改动，**必须先做** |
| 1 | 确定量 diff（op 计数 / 同步点数） | 性能与簿记类改动，不受时钟抖动影响 |
| 2 | 函数级严格相等 | **纯重构**：同一批 op、同一输入、同一求值顺序，只是少算几遍 |
| 3 | 噪声本底比较 | 引入真实数值扰动的改动 |
| 4 | 任务指标（成功率 / 感知质量） | 准入 |

- **层 0 常常就够**：比较三个量级——改动引入的扰动、下游表示精度、系统自身 run-to-run 噪声。
  扰动低于后两者时，数值判据在原理上判不出东西，再往下跑只会返回噪声。
- **层 2 只对纯重构合法**：换后端 / 换 dtype / 换 kernel / 改求和顺序之后，严格相等是先验不可能，
  不是待测假设。
- **层 3 判「同量级」不判「相等」**：先量 base-vs-base 当本底，再看 arm-vs-base 是否落在同一量级；
  系统若有阈值跳步类的混沌放大，先关掉再比。

**性能类用层 1、数值类用层 3、准入用层 4，三者不混。**

#### 引入外部模型或服务时，层 0 是复现它自带的样例

**先跑通对方的例子，再测自己的东西**：用它的输入、参数、参考输出比到同量级，没样例就跑它的
e2e 测试。跳过这步，后面每个判据都建在「对方按我们以为的方式工作」上。逐项对齐维数与排布、
单位与取值域（归一化？增量还是绝对）、枚举名是否真被这份权重覆盖、帧数 / chunk / fps。

**返回 200 不是判据**，只校验 schema 的接口对语义不设防。**生成类结果先看产物再算指标**：
标量分不出「不准」与「没在预测」，整幅画面的差分也分不出「主体在动」与「背景在抖」。

> Cosmos3 `forward_dynamics`：三发 200 被记成「形状被接受」，实际是 7 维塞进要 10 维的
> embodiment、domain 名这份权重没训过、`num_frames=16` 被静默截成 13。样例就在已下载
> checkpoint 的 `assets/` 里，跑一遍 3 分钟；没跑，两天的实验整批作废。

## 文档结构：一篇一个结论

主线、解释性膨胀与组织轴的通则在 `narrative-spine`，本节只写 feature / exp 文档的章节模板。

**没有重点的报告等于没有结论的实验。** 模型默认按执行顺序平铺（L0/L1/L2 各一节各十几行），
读者被迫认为它们同等重要，读完记不住任何一条。

1. **开篇就是结论**：第一节叫「结论」，一句话 + 最多一张表，这句话要能独立成立。
2. **写出三个并列的「核心结论」＝还没想清哪个是主的。**
3. **支撑读数 ≤ 3 条**，按重要性排，不按实验编号排。
4. **方法与前提降到后面**：环境、换算、参数核实回答「怎么得到的」，必须在但不占开头。
5. **删掉空占位表**：`| 待填 |` 是把没做的事伪装成内容，总览表里一行 `⬜ 待跑` 就够。
6. **L0/L1/L2 留在总览表**，正文按「结论 / 证据 / 单独要指出的事 / 可信度边界 / 方法」组织。
7. **结论收口在 feature 文档，exp 文档只放实验记录。** 一个数只有一个定义处，别处用链接。

## 文档语态

归 `narrative-spine` 的「直接陈述当前为真的内容」：写真值而不写「原先以为 X 其实是 Y」、
第三人称、不写规划史、一组事实写清单、标题写问题本身、以及收尾的自检 grep。

本 skill 只补一条实验文档专属的例外：**「关于世界的否定发现」要留**。被测系统的否定事实
（「aiter 没有 AdaLN 形态的 kernel」「假设不成立，RMS 0.05」）是实验产出，往往还是最贵的
那部分；被否决的候选写进专门的「排除 / 不做」表当长期决定。删掉的只是对自己旧措辞的修订说明。

## Workflow

### Phase 0 — Problem Formulation（不过不许进 Phase 1）

**`π(observation) → action` 是单值函数吗？** ① 决定 action 所需的信息是否都在 observation 里；
② 同一 observation 在不同 episode 下是否对应不同 action（是则问题不可解——列出所有随机化变量，
确认它们要么固定、要么在 observation 中）；③ observation 的构成顺序与 action 语义
（absolute / delta / target）在训练与评估两端是否一致。

不完备时：加进 observation（最直接）／固定该变量（诊断用）／换 vision 等富信息模态（长期）。

> Franka pick-cube：cube 位置每 episode 随机化却没进 observation，10+ 组实验（DART、闭环 IK、
> noise aug、history）全部 0% 成功率。**所有调优都是在一个不可解的问题上做无用功。**

### Phase 1 — 开跑前写设计

先过**决策价值门**，再写文档：Phase 0 结论、一句话假设、方案、预期、判据选**阶梯**哪一层。

```markdown
## Exp-<ID>: <标题>
### 假设 / 决策价值
<一句话>；否定结果会改变: <什么>
### 方案
- 脚本 / 关键参数 / 对照组 / 变量
### 预期与判据
- 成立: <metrics>　不成立: <metrics>　判据: 层 <n>
### 结果 / 分析 / 结论与 Next Step
（待实验）
```

### Phase 1.5 — Smoke Test

预估 > 10 分钟的实验，先用极小参数（`n_episodes=2, max_steps=50`）跑 1–2 分钟：
验证不 crash、输入输出格式正确、关键计数符合预期。**不看指标**，只验管线畅通。

### Phase 2 — 过程中实时记录

error 与意外行为立即记；多轮迭代用表格追踪 `| 轮次 | 问题 | 修复 | loss | eval |`。

### Phase 3 — 写回

结果（原始表格）→ 分析（假设成立与否、与 baseline 的 delta、意外发现）→ 结论（一句话）→
Next Step（按优先级）。然后清理一次性脚本与中间文件（保留输出与日志）、删掉设计阶段的过渡内容、
过一遍上面两节的自检。

删草稿后最常残留三样：**平均着墨的分级标题**、**「原先以为 X、实测是 Y」的衔接句**，
以及**为了自包含而复述到 exp 里的结论**（该留在 feature，这里放链接）。

### Phase 4 — 归档与冻结

功能落地且不再迭代时**归档而非删除**——代码与 git diff 说不清「为什么这么设计、试过什么、
为什么否决」，这份决策依据是事后最难重建的东西。加 `> Status: as-built (frozen YYYY-MM)。
最新设计以 <活文档> 为准。` 后只读；耐久的 rationale 上提到活文档，feature 文档退化为
「链接活文档 + 保留实验证据」；可选移入 `docs/archive/`；partN / featureN 序号不外泄。

### Phase 5 — 维护总览表

```markdown
| Exp | 假设 | 状态 | 关键结果 | 结论 |
|---|---|---|---|---|
| F4 | noise aug 改善 shift | ✅ done | 全部下降 | noise 有害 |
```

### Phase 6 — 无人值守长实验

**默认选最推荐方案继续**，在文档里写清候选、选中理由，以及放弃项是否值得回头——值得就在
`task.md` 里补一行（schema 归 `task-loop`），理由留在本文档，那一行只放链接。

每轮结束、规划下一轮之前回到文档开头，问四件事：还在解决**最初的问题**吗，还是在解决子问题的
子问题？迭代 ≥ 3 轮仍没逼近目标，该不该跳出当前路径？有没有更直接的方案被当时的「最推荐」挡掉？
下一轮过决策价值门了吗、量级配得上主线瓶颈吗？

偏离就开 `## 路径回溯 / Pivot`，记原始目标、当前位置、pivot 理由、新方向第一步。
**不要假装没偏离**——被诚实记录的 pivot 比「看起来线性推进」的实验更有价值。

**什么情况才停下来问人**，以及环境错误该先自修几次，归 `experiment-budget-gate` 的
「先自修，再中止」与「硬性中止」——那是唯一一份清单，本 skill 不另列。

## Commit Convention

通用写法归 `code-hygiene`。实验类只加一条：**subject 带实验编号**，
开跑前 `F4 noise sweep: experiment design and hypothesis`，
跑完 `F4 noise sweep results: noise aug harmful on Franka, all sigma degrade E1`。

## Key Principles

1. **不改变决策的实验不跑** — 开跑前问「否定结果会改变主线吗」，且量级要配得上主线
2. **判据从任务指标往下选** — 严格相等只对纯重构合法，越过那条线它是先验不可能
3. **先审后做** — Phase 0 不过不动手
4. **先写后跑** — 设计先进文档，不跑完补
5. **数据说话，对比呈现** — 结论要有量化证据和 baseline delta，不写「感觉上」
6. **不删历史** — 失败实验同样保留，`❌ disproved` 排除了假设空间
7. **自主但不迷路** — 每轮结束回到文档开头重读原始问题
8. **一篇一个结论，为人写不为检索写** — 语态与结构通则见 `narrative-spine`
9. **结论收口在 feature，exp 只放记录** — 一个数只有一个定义处，别处用链接；要改两个文件就是散落
