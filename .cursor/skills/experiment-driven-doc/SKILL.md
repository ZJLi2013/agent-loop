# Experiment-Driven Documentation

将「假设 → 实验设计 → 执行 → 结果 → 分析 → 下一步」全流程记录到项目文档中，
做到任何人（包括未来的自己）都能复现思路和决策依据。

## 与 long-running-agent-harness 的边界

- `experiment-driven-doc` 负责实验假设、设计、结果、分析和结论。
- `long-running-agent-harness` 负责跨会话任务拆解、runbook、进度日志和交接状态。
- 对长实验：先用 harness 建立 `.cursor/harness/`，再用本 skill 维护正式实验文档。

## 文档结构：重点必须压倒性，切勿平均着墨

**没有重点的报告，等于没有结论的实验。** 当前一代模型（GPT / Claude 系）默认按
**执行顺序**平铺——L0、L1、L2、L3 各给一个同级标题、各写十几行——读者被迫认为它们同等重要，
读完记不住任何一条。正确的组织轴是**重要性**，不是执行顺序。

### 规则

1. **开篇就是结论。** 第一节标题就叫「结论」，内容是**一句话 + 最多一张表**。
   这句话要能独立成立，不依赖读者往下读。
2. **一篇文档只有一个结论。** 其余全部是它的**证据**、**边界**或**副产物**，
   在结构上就要低一级。如果你写出了三个并列的「核心结论」，说明还没想清楚哪个是主的。
3. **支撑读数不超过 3 条，且按重要性排序**，不按实验编号排序。
4. **方法与前提降到后面。** 几何换算、参数核实、环境配置回答的是「怎么得到的」，
   不是「是什么」。它们必须在文档里（可复现性），但不该占据开头。
5. **删掉空占位表。** `| 待填 | 待填 |` 是把没做的事伪装成内容，
   在总览表里写一行 `⬜ 待跑` 就够了。
6. **执行级别（L0/L1/L2…）留在总览表里，不要升成正文标题。**
   正文按「结论 / 证据 / 需要单独指出的事 / 可信度边界 / 方法」组织。

### 自检

- **只读前 10 行，能不能复述结论？** 不能就是开头没写对。
- **删掉任意一个非结论章节，结论还成立吗？** 成立，说明那节该降级、折叠或删掉。
- **每个标题占的篇幅，是否与它对决策的影响成正比？** 明显不成正比就重组。

## 文档语态：陈述当前为真的内容，不解释推导过程

对话里可以铺垫、可以解释；**文档只陈述当前为真的内容**。三种最常见的污染：

### 1. 用「否定旧结论」代替「陈述新结论」

文档没有记忆，读者也没读过草稿。把结论写成对一个未出现在文中的旧说法的反驳，
读者得先重建那个旧说法才能读懂这句话。

| 写成了 | 应该写 |
|---|---|
| 占用不足的说法对主力形状不成立 —— tile 比假定的聪明 | 主力形状的 wave 占用 98.8% —— hipBLASLt 按形状挑 tile |
| 结果推翻了先前的直觉排序：最大一块不是 RoPE 也不是 norm，而是 paged-KV 的 78 ms | 最大一块是 paged-KV 的写入与索引簿记：78 ms |
| 这一轮把它从「已知该做」变成「已定价 30 ms」 | 这条 TODO 现在有了定价：30 ms |
| 顺序视图纠正了一处：有 3 个同步点，不是 1 个 | 每个 block 有 3 个 host 同步点 |
| 先前那 100 ms 无法定价，是因为不知道形状 | 这 100 ms 的定价来自 trace 里的形状 |
| 这张表推翻了「先融 norm」这个方向 | 这张表把融合靶子定在 qk-norm + RoPE |

判别方法：**如果被否定的那个说法只存在于本文档的历史版本或上一轮对话里，它就不进正文。**
那部分历史 git 已经存了，正文里留着只会让读者替一个不存在的误解买单。

### 2. 但不要因此删掉「关于世界的否定发现」

上一条约束的是对自己旧措辞的修订说明，不是所有否定句。区分：

- ✅ **保留**：关于被测系统的否定事实 —— 「aiter 没有 AdaLN 形态的 kernel」
  「`causal=False`，所以没有被 mask 掉的浪费」「假设不成立（RMS 0.05）」。这些是实验产出，
  而且往往是最贵的那部分（见 Key Principle 6）。
- ✅ **保留**：被否决的候选方案 —— 但写进专门的「排除 / 不做」表，作为**长期有效的决定**
  （`❌ 换 aiter norm：实测只值 1pp`），不是散在结论段里的旁白。
- ❌ **删掉**：对本文档上一版措辞的修订说明。

（`不成立` 这个词因此两义：`假设不成立` 是实验的设计产出，保留；`XX 的说法不成立` 多半是第 1 类。）

### 3. 对话人称与元叙述

- 用第三人称 / 无人称：「trace 显示…」「这个形状占用 98.8%」。
  不用「我们发现」「你可以看到」「如前所述我搞错了」。
- 不写只在当前会话里有意义的话：「要我继续吗」「下面我来更新表格」「这一节我重写了」。
- 不写「值得注意的是」「需要说明的是」这类零信息引导语，直接说那件事。

### 语态自检（并入 Phase 3 回填）

grep 一遍：`其实|原来|当初|先前|之前以为|推翻|纠正|不再是|直觉|我们发现|可以看到|值得注意的是|需要说明的是`

逐条判断属于第 1 类（改成陈述）还是第 2 类（保留）。标题和摘要行优先改——
它们被读到的次数最多，也最容易写成「对旧认知的更正」。

## Workflow

### Phase 0: Problem Formulation 检查（必须最先做）

**核心问题：`π(observation) → action` 是单值函数吗？** Phase 0 不通过，禁止进入 Phase 1。

1. **观测完备性**：决定 action 所需的全部信息都在 observation 里吗？
   若 action 依赖某变量（目标位置、任务 ID、环境参数），该变量**必须**在 observation 中。
2. **映射唯一性**：同一个 observation 在不同 episode / context 下是否对应不同 action？
   是则问题不可解。检查方式：列出所有随机化变量，确认它们要么固定、要么在 observation 中。
3. **数据-评估一致性**：observation 的构成与顺序、action 的语义（absolute / delta / target），
   在训练数据与评估流程两端是否一致？

observation 不完备时：加入 observation（最直接）／ 固定该变量（诊断用，证明可解后再推广）／
换 vision 等富信息模态（长期）。

> **教训来源**：Franka pick-cube 实验中 cube 位置每 episode 随机化但未加入 observation，
> `π(s)→a` 不是单值函数。历经 10+ 组实验（DART、闭环 IK、noise aug、history、时序修复）
> 全部 0% 成功率，最终才追溯到 problem formulation 层面。
> **所有后续调优都是在一个不可解的问题上做无用功。**

### Phase 1: Before Experiment — 写入实验设计

编写代码或启动实验**之前**先更新文档：Phase 0 结论、一句话假设、实验方案（脚本 / 参数 / 对照组 / 变量）、
预期（假设成立与不成立分别期望看到什么）、量化评估标准。

```markdown
## Exp-<ID>: <简短标题>

### Phase 0 确认
- 观测完备性 / 随机化变量: <...>

### 假设
<一句话>

### 实验方案
- 脚本 / 关键参数 / 对照组 / 变量

### 预期
- 成立: <expected metrics>   不成立: <expected metrics>

### 结果 / 分析 / 结论与 Next Step
（待实验）
```

### Phase 1.5: Smoke Test

实验预估 **> 10 分钟** 时，先用极小参数（`n_episodes=2, max_steps=50`）跑 1–2 分钟：
验证无 crash、输入输出格式正确、关键计数符合预期。**不看指标**，只验管线畅通。
smoke test 失败就在调试表格里记录并修复，避免浪费长等待。

### Phase 2: During Experiment — 实时记录

出现 error / 意外行为立即记录。多轮迭代用表格追踪：

```markdown
| 轮次 | 问题 | 修复 | loss | eval 结果 |
|---|---|---|---|---|
```

### Phase 3: After Experiment — 写回结果与分析

1. **结果**：原始数据表格
2. **分析**：假设是否成立（用数据说话）、与 baseline / 前序实验的 delta、意外发现
3. **结论**：一句话
4. **Next Step**：从结论推导，按优先级排列
5. **清理临时产物**：删除本地与远端节点上的一次性脚本、中间文件；保留实验输出和日志
6. **精简文档**：删除或折叠设计阶段的过渡性内容（Phase 0 确认、假设推演、预期结果），
   只留可复现要点、核心数据、结论与 Next Step
7. **过一遍结构自检与语态自检**：见上面两节。
   删掉设计草稿之后最容易残留两样东西——**平均着墨的分级标题**（L0/L1/L2 各占一节，
   结论淹没在中间）和**「原先以为 X，实测是 Y」的衔接句**（草稿删了，对草稿的反驳还留着）。

### Phase 4: 归档与冻结（Archive & Freeze）

**区分「活文档」与「历史档案」，归档而非删除。** 代码 + git diff 只能说明「现在是什么」，
说不清「为什么这么设计、试过哪些方案、为什么否决」——这份决策依据是事后最难重建的东西，
删掉等于丢进 git 考古坑（理论上还在，实际没人翻）。

时机：功能已落地并验证、不再有后续迭代。

1. **加冻结状态行**：`> Status: as-built (frozen YYYY-MM)。最新设计以 <活文档路径> 为准。`
   冻结后只读。
2. **单一真相来源**：活文档持续演进反映最新状态；冻结的 featureN / expN 只描述「当初怎么来的」。
   耐久的设计 rationale 上提到活文档，feature 文档退化为「链接活文档 + 保留实验证据」。
3. **可选物理归档**：移到 `docs/archive/`，让活跃目录一眼看出「哪些还在动」。
4. **内部序号留在内部**：partN / featureN 不要泄漏到对外文档。

### Phase 5: 维护总览表

```markdown
| Exp | 假设 | 状态 | 关键结果 | 结论 |
|---|---|---|---|---|
| F3 | BC E1 N=5 > SO-101 | ✅ done | 90% vs 0% | 7-DOF 冗余有效 |
| F4 | noise aug 改善 shift | ✅ done | 全部下降 | noise 有害 |
```

### Phase 6: 无人值守长实验（Autonomous Long-Run Mode）

**默认选最推荐方案继续**，不停下等人决策；在文档中写明候选方案、选中哪个及一句话理由、
被放弃的是否值得回头（标 backlog）。只有三种情况停下来等人：消耗显著资源
（> 1 节点 × 24h 或费用敏感）、破坏性操作（删数据 / 覆盖 checkpoint / 强推生产分支）、
三轮以上无进展。

**每轮结束、规划下一轮之前，回到文档开头**重读最初的问题和总览表，问三件事：

> 1. 现在做的事还在解决**最初的问题**吗？还是在解决「为解决最初问题而引入的子问题的子问题」？
> 2. 迭代了多少轮？≥ 3 轮仍没逼近原始目标，是不是该跳出当前路径？
> 3. 有没有更直接的方案被当时的「最推荐」挡掉了？现在重估，那条路是否反而更优？

偏离了就开 `## 路径回溯 / Pivot` 段落，记录原始目标、当前路径走到哪、为什么 pivot、新方向第一步。
**不要假装没有偏离**——被诚实记录的 pivot 比「看起来线性推进」的实验更有价值。

**硬性中止条件**（满足任一即停，等人介入，并写 `## Auto-Stop Report`）：
连续 3 轮指标无改善（或在 noise 范围内波动）／连续 2 轮同一环境依赖错误且修复无效／
资源超预算／发现 Phase 0 假设可能不成立。

## Commit Convention

commit message 包含实验 ID：

- 实验前：`F4 noise sweep: experiment design and hypothesis`
- 实验后：`F4 noise sweep results: noise aug harmful on Franka, all sigma degrade E1`

## Key Principles

1. **先审后做**：任何实验之前先过 Phase 0 —— observation 是否完备、映射是否唯一
2. **先写后跑**：先写设计再执行，不要跑完补文档
3. **数据说话**：结论必须有量化证据，避免「感觉上」
4. **对比呈现**：每个结果都与 baseline 和前序实验做 delta 对比
5. **决策可追溯**：next-step 从当前结论推导，形成清晰因果链
6. **不删历史**：失败实验同样保留（✅ done / ❌ disproved），它们排除了假设空间
7. **自主但不迷路**：长实验可不等人反馈，但每轮结束必须回到文档开头重读原始问题
8. **重点压倒性**：一篇文档一个结论，开篇一句话说完，其余都是它的证据或边界。
   平均着墨等于没有结论——**按重要性组织，不按执行顺序**
9. **陈述而非解释**：写当前为真的内容，不写「原先以为 X、其实是 Y」。
   关于被测系统的否定发现和被否决的方案都属于结论，保留
