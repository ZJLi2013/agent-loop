# Research → Blog（文献调研到自媒体）

把一次深度文献调研，沉淀成一篇对外读者能读懂、可信、且没有"AI 味"的博客。
核心原则贯穿始终：**内部消化文档 与 对外博客 是两份东西，不要混**——
内部可以第一/第二人称、带项目私料、带主观下注；对外必须第三人称、客观、可核实。

## Workflow

### Phase 1: 文献调研 + 事实核实（先建"事实底座"）

1. **读源头**：综述优先（给全局分类法），再按需下钻到关键论文。记录每篇的
   视角/分类维度（例：一篇按"表征类型"切、一篇按"信息流层次"切），标出它们是否正交。
2. **联网核实一切"已开源/已发布/已解决"类断言**：不要凭论文标题脑补。逐条查
   GitHub / HuggingFace / 项目页，确认**代码、权重、数据、训练脚本**各自的发布状态
   （常见坑：只发推理不发训练；只发 metadata 不发原始数据；需申请权限的基座）。
   把核实结果写成事实清单，后续所有断言只能引用这份清单。
3. **区分事实与判断**：事实（谁发布了什么）与判断（谁更有前景）分开记，判断必须可追溯到事实。

### Phase 2: 内部消化（study 笔记，允许主观）

- 先写**内部 study 文档**：landscape、分类法对照、与自己项目/资源的关系、投资/优先级判断。
- 内部文档可以主观、可以第一人称、可以放私有工程细节（如内部 repo、集群、ROCm 状态）。
- 这一步是"想清楚"，不是"写给别人"。**不要**把这份直接当博客发。

### Phase 3: 谋篇（结构先于文字）

1. **一条主线**：全篇只讲一个收敛的故事线，其它都是支撑。开篇一句话点明主线。
2. **高到低组织**：先给高层地图（分类/坐标系），再下钻到主线细节。
   若发现"先深入讲 X，后面才说 X 只是三者之一"——倒序了，调过来。
3. **去重扫描**：同一批概念/同一个决策清单只讲一次。多个小节都在重述
   "各选项优劣 + 推荐"时，合并成一节。列出每节"独有信息"，无独有信息的节删掉或并入。
4. **保留高信息密度结构**：对比表、坐标轴/流程示意图（ascii 或 mermaid）该留就留，
   它们不是"AI 味"，是干货。

### Phase 4: 客观化 + 去 AI 味（对外稿的关键一步）

**客观化（内容层）：**
- 全文第三人称，删掉一切"面向读者/面向自己"的解释（"回到你的问题""我的建议""帮你梳理"）。
- **不 overclaim**：把"解决了/已兑现/护城河"这类强断言，降级到事实支撑得起的程度
  （例："工程门槛已解阻" ≠ "根本权衡消失了"）。区分"方向性投入"与"成熟范式"。
- **自洽性检查**：把全篇的关键判断两两对照，确认不打架
  （常见冲突：某处说 X 便宜/已解决，另一处的对比表却说 X 贵/有噪声）。
- **诚实的取舍**：涉及路线选择时给出"什么目标该选什么"，而不是单捧一条。

**去 AI 味（形式层）——对照清单逐条清理：**
- 删掉用作强调的 `>` blockquote 批注块，化成正常段落。
- 收掉正文里滥用的 `**加粗**`，只在概念首次出现时少量保留。
- 删标记语："一句话戳破""关键分水岭""换句话说""但要诚实""TL;DR""说白了"等。
- 少用破折号堆砌的短句碎片和箭头，改成完整句子的自然段。
- 章节内避免"清单感"：能用一段连贯叙述讲清的，不要拆成一堆 bullet。

### Phase 5: 自媒体成品（标题 / 配图 / References / 内外分离）

1. **标题**：给 3–5 个候选，覆盖不同风格（科普向 / 干货向 / 观点向）。
   微信公众号标题要有"钩子 + 具体名词"，避免纯术语堆砌；正文首段承接标题的钩子。
2. **配图**：
   - **结构图**（坐标系、流程、对比）→ 用 **mermaid / ascii**，文字渲染清晰、可维护；
     **不要**用文生图做带精确文字标签的图（易糊字）。
   - **封面/概念图**（hero）→ 可用文生图，但描述里**明确 "no text"**，走概念/隐喻，
     统一配色与极简风；公众号封面常用 2.35:1 头图 + 1:1 缩略图。
3. **References**：对外稿必须有独立引用章节，把论文/仓库/项目页配上可点链接
   （arXiv / GitHub / 项目主页），正文里的"某综述指出"要能在此落地。
4. **内外分离归档**：
   - 对外博客里**不出现**本地文档路径引用（`见 docs/study.md §8` 这类）、内部工程细节、
     公司/集群/私有 repo 信息——这些留在内部 study 文档。
   - 若对外稿需要承接内部内容，做法是把内部洞见**改写**进对外稿，而不是链接内部文件。
   - 内部 study 文档保留完整（含主观判断、私料），作为"活文档"持续更新。

## Key Principles

1. **内外两份稿**：内部 study（主观、私料、第一人称）与对外 blog（客观、可核实、第三人称）严格分离。
2. **先核实再断言**：任何"已开源/已解决/已发布"都要联网逐条查过，事实清单是唯一真相来源。
3. **结构先于文字**：单一主线 + 高到低 + 去重；先搭骨架再填肉。
4. **不 overclaim、要自洽**：强断言降级到事实支撑得起的程度，全篇关键判断两两对照不打架。
5. **去 AI 味是形式活**：删 blockquote 批注、收加粗、删标记语、消清单感——但保留对比表和结构图这类真干货。
6. **图分两类**：结构图用 mermaid/ascii（清晰可维护），封面用文生图（概念、no text）。
7. **对外不漏私料**：本地路径、内部 repo、集群/ROCm 等工程细节不进对外稿。
